Simple Loot Council — Feature Guide

Sep 25, 2026 · Laxx

Simple Loot Council (SLC) runs loot council voting for WoW retail 12.1.0 (Midnight), synced live across every raider's client. Retail has no master looter, so the council votes on items sitting in a raider's bags during the 2-hour trade window; the loot master awards, and the holder trades the item across.

Beta SLC is in beta as of 0.40.0. Every participant needs the addon; players without it still show up in the council table, they just never answer.

Getting started

  1. Install it. With WowUp: Get Addons → Install from URL → paste https://github.com/SimpleLootCouncil/SimpleLootCouncil-Beta. WowUp keeps it updated. By hand: download the zip from the latest release and unzip the SimpleLootCouncil folder into World of Warcraft\_retail_\Interface\AddOns.
  2. /reload in game. No client restart is needed, even for a first install.
  3. Type /slc to open settings. /glc works as an alias for every command.
  4. The group leader runs loot by default. Hand it to someone else with /slc lootmaster Name-Realm.
  5. Add your council: /slc council add Name-Realm, or tick guild ranks under Council by guild rank in settings.
  6. Try it solo first: /slc test 6 opens a simulated run with six items so you can see every window.
If WowUp says Addon Installation Failed, go to Options → Addons and clear the GitHub Personal Access Token field, then try again.

No library dependencies. Optional integrations: WowUtils (wishlist and sim columns), SimulationCraft (profile export), RCLootCouncil / Loothing (history import). Disable RCLootCouncil's own looting if you run the SLC funnel - the two conflict.

How a loot run works

A run goes from the boss kill to a completed trade in seven steps, and every step is shared live with the group.

  1. Opt in. On entering a raid, the loot master is asked "Use Simple Loot Council for this raid?". Raiders are then asked whether to take part. Nobody is asked anything until the loot master says yes.
  2. Collect. With the optional group-loot funnel on, the loot master rolls Need and participating raiders pass, so loot lands in one pair of bags. Without it, raiders keep what they win and the council still votes on it.
  3. Stage. The loot master queues items privately in the Loot Queue (/slc queue), from their own bags or, if enabled, council members' bags. Staging opens nothing on anyone else's screen.
  4. Start. Start run sends the items to the group. Every raider gets the Loot Response window; the council gets the Loot Council table. Items can be added to a run in progress.
  5. Respond. Raiders pick a response (Mainspec, Offspec, Transmog by default, all configurable), add an optional note, or pass. Unusable items can auto-pass.
  6. Vote and award. The council votes; the loot master awards. Awards can go to a player or "for a reason" (disenchant, guild bank, free).
  7. Trade. Whoever holds the item sees it in Loot to Trade. Opening a trade with the winner fills the window automatically; you press Trade. The award is marked delivered only once the item has actually changed hands.

The boss each item dropped from is recorded automatically, from the kill or from the Adventure Guide. Addon messages are blocked during boss encounters and Mythic+, so loot seen mid-fight is queued and sent when the pull ends; normal combat is fine.

For the council

The Loot Council table shows every candidate for every item, and each council member's votes reach everyone within a second. Reopen it any time with /slc vote (/slc v).

Column / featureWhat it shows
Item railEach item with its state: OPEN, AWARDED, MISSING, OWED, REMOVED, plus boss, difficulty and upgrade track
NameClass-coloured candidate, spec, item level, and a coined tag if they bonus-rolled this item
ResponseTheir answer in its button colour, or Waiting, Pass, Auto-pass
UpgradeItem-level change against what they have equipped, and tier-set progress (3/4 set, +2set, +4set)
Wishlist / SimFrom WowUtils, when installed: is it on their list, BiS, and the simulated DPS gain
Note[+] when they wrote one; hover to read it
RollTheir roll, or assign for a generated one
VotesVote count, with Vote / Unvote buttons

Hover a candidate for the council tooltip: their most recent loot, who else has won this item, attendance (nights this season), alt/main link, guild note and officer note (if you can see it), and their equipped item with sockets and average item level.

Voting rules are shared group-wide so a vote means the same thing on every screen:

  • Council may vote for themselves (on by default)
  • Allow voting for several candidates per item (off)
  • Hide vote counts until you have voted, to stop bandwagoning (off)

Rolls: right-click a row or item to ask one player, everyone on a response, or the whole raid to roll; or generate rolls instantly. /slc roll ask, /slc roll random, /slc roll clear do the same for every unawarded item.

Start requests: if the loot master allows it, council members can propose a run from their own queue; the loot master approves or declines.

Reliability

A run survives reloads, disconnects and loading screens on any client, including the loot master's.

  • Reload recovery. A raider, council member or loot master who /reloads mid-run gets the run back from the group within seconds: responses, notes, votes, rolls and coins intact. A delegated loot master recovers too.
  • Nothing owed is forgotten. The trade ledger is saved, so a reload never loses who you owe what.
  • Delivery is checked against your bags, not assumed. An item that was equipped, sold, or traded to the wrong player is flagged, and the loot master is told.
  • Loading screens and crowd control. The game closes addon windows on every zone change, fear or mind control; SLC reopens the ones you did not close yourself.
  • Boss encounters and Mythic+. Blizzard blocks addon messages there. SLC queues outgoing messages in order and sends them when the block lifts.
  • Version warnings. You are told in chat if someone in the group runs a different build.
  • Every string is translatable. The addon ships in English; translators can work from Locale/enUS.lua.

Testing and reporting bugs

Most of SLC can be tried solo; a real bug report needs the log from every client involved.

Solo checks

  • /slc test 6 - a simulated run with six classic-raid items. Open every window, respond, vote, award.
  • /slc test [item link] from heroic <boss> - test a specific item, attributed to a boss and difficulty.
  • /slc testcoin 2 - fake a bonus roll on item 2 to see the coined tag. No coin is spent and nothing reaches history.
  • /slc ping - checks the whole message path, round trip.
  • /slc history, /slc team, /slc queue, /slc trades - browse each window.
  • Test awards from /slc test never reach your real history.

With a friend: start a test run, then /reload one client mid-run and check that everything comes back.

Before testing, run /console scriptErrors 1 so Lua errors show on screen. BugSack and BugGrabber help too.

When something goes wrong, send:

  1. /slc log from every affected player, copied out of the window.
  2. /slc dump from the loot master.
  3. What you clicked, and what you expected to happen.

The log is timestamped and survives reloads, so comparing the loot master's with a raider's usually shows which message went missing. After an update, /reload twice before reading the log: the first reload still shows the old build's state.
